# 血缘语义、校验与重算规则

本文档说明指标注册中心的血缘图模型、单位与维度兼容性校验，以及全量/增量重算的精确定义。

## 1. 血缘图模型

* 节点：每个指标 ID（base 或 derived）。
* 有向边方向为 **上游输入 -> 下游消费者**：存在边 `a -> b` 当且仅当派生指标 `b`
  的某个公式槽位绑定到指标 `a`。
* 图是**不可变快照**：每次提交都会基于当前全部定义重新构建一个新图并原子发布，
  已发布的图不会被原地修改，读者据此看到一致的完整版本。
* `Inputs(id)`：某派生指标的直接输入。
* `Downstream(id)`：直接消费 `id` 的派生指标。
* `Impact(id)`：所有**传递依赖** `id` 的派生指标（若 `id` 自身为派生，也包含自身），
  按输入先于输出的**拓扑序**返回，用于变更影响分析与增量重算。

### 环检测

注册/更新派生指标 `x`（其输入集合为 `I`）时，新增边 `i -> x`。
环的判定基于边方向：当且仅当某个 `i ∈ I` 能从 `x` 沿下游方向到达时闭合成环，即
图中存在 `x -> ... -> i`。

* 自引用 `x` 引用自身：立即拒绝（`metric.ErrCycle`）。
* 间接环：`x` 的某个下游最终回到新输入，例如 `d -> c` 已存在，再让 `c -> d`，
  得到 `c -> d -> c`，拒绝注册。
* 菱形（`a -> b, a -> d, b -> c, d -> c`）不是环，允许注册。

检测在校验通过前进行；被拒绝的注册**不写 WAL、不发布**，已提交状态完全不变。

### 变更影响分析

* 基础数据更新：影响 `Impact(baseID)`。
* 派生定义变更（新版本）：影响该派生指标自身及其全部下游。
* 指标下线（`Retire`）：该指标状态置为 retired、定义历史保留；其下游进入 dirty。
  已下线派生指标不再保留结果，也不能作为新派生指标的输入。

## 2. 维度语义

派生指标 `d` 维度为 `D_d`，某输入指标 `i` 维度为 `D_i`，要求：

```
D_d ⊆ D_i     // 每个输出维度都必须被每一个输入覆盖
```

不满足则拒绝（`metric.ErrDimMismatch`）。这样输出的每个维度坐标都能从每个输入取值。

* **维度投影 / 上卷**：当输入维度是输出维度的真超集（多出更细粒度维度）时，
  对坍缩到同一输出维度组合的点做 **SUM 聚合**。例如输入维度
  `[region, product]`、输出维度 `[region]`，则同 region 下所有 product 求和。
* **多输入对齐**：各输入分别投影到输出维度后，按键做 **inner join**——
  某个维度键在任一输入中缺失，则该键不出现在结果中（缺失即口径不完整，不补零），
  以保证结果确定、可复现。
* 维度元组以 NUL 连接作为内部 map 键，输出键顺序经排序处理，计算不依赖 map 遍历序。

## 3. 单位语义与换算规则

每个单位由一个**量纲向量**和到基准单位的换算系数描述：

```
baseValue = value * Factor + Offset      // Offset 仅用于温度等仿射单位
value     = (baseValue - Offset) / Factor
```

* **兼容性**：两个单位的量纲向量相同才兼容（`m` 与 `km` 兼容；`m` 与 `s` 不兼容，
  返回 `metric.ErrUnitIncompatible`）。
* **内置线性单位**：
  * 长度（基准 `m`）：`km=1000`、`cm=0.01`、`mm=0.001`；
  * 时间（基准 `s`）：`min=60`、`h=3600`、`day/d=86400`；
  * 质量（基准 `kg`）：`g=0.001`、`t=1000`；
  * 货币（基准 `USD`）：`CNY=0.14`、`EUR=1.08`（显式固定汇率规则）；
  * 无量纲：`""`、`1`、`count`、`ratio`、`times`；`percent/pct=0.01`。
* **仿射单位（温度）**：基准 `K`，`C`（Offset 273.15）、`F`（Factor 5/9 + Offset）。
  温度单位之间量纲相同可换算；但参与乘除时按线性量纲处理。
* **复合单位**：支持 `m/s`、`km/h`、`m^2`、`USD/USD` 这类由已注册简单单位
  按“分子乘积 / 分母乘积”组成的名称，`^n` 表示幂次；`USD/USD` 归约为无量纲。

### 派生计算中的量纲推断

公式 AST 上做自底向上的量纲推断（数字字面量为无量纲）：

| 运算 | 结果量纲 |
|------|----------|
| `a + b`, `a - b` | `a`、`b` 量纲必须相同，结果维持该量纲 |
| `a * b` | 量纲向量相加 |
| `a / b` | 量纲向量相减 |

注册时将推断出的结果量纲与派生指标**声明单位**的量纲比较，不一致即拒绝
（`metric.ErrUnitIncompatible`），例如：

* `m + s`：拒绝；
* 公式是 `a*b`（量纲 `length*time`）却声明单位 `m`：拒绝；
* `km + m` 声明输出 `cm`：允许。

### 归一后再计算

计算每个维度键时：

1. 将每个输入值从其单位换算到该量纲的**基准（归一）单位**
   （如 `km -> m`、`CNY -> USD`、`C -> K`）；
2. 在归一单位上执行四则运算；
3. 将结果从推断量纲的基准单位换算为派生指标**声明的输出单位**后存储。

因此兼容单位的混用是确定的，且“先归一、后计算、再转回”只有一种结果，
保证全量与增量、单次与重启后重算结果一致。除零等逐键算术错误会确定性地跳过该键
（不作为整体失败）。

## 4. 重算语义

### 全量重算（`Engine.Full`）

按血缘拓扑序（输入先于输出）计算所有 active 派生指标；派生输入取本轮已算出的结果，
基础输入取已提交基础数据。

### 增量重算（`Engine.Incremental(changed)`）

1. 对每个变更根取 `Impact(root)`，只保留 active 的派生指标，得到受影响子图；
2. 其余派生指标的结果 map **原样共享、绝不修改**（未受影响指标结果不变）；
3. 受影响子图仍按拓扑序计算，输入若也在子图内则取新结果，否则取已提交结果。

**一致性保证**：增量重算与全量重算在同一已提交快照上逐键相等（测试
`TestIncrementalEqualsFull`、`compute` 层 `TestIncrementalLeavesUntouched` 断言）。

### dirty 集合与提交

* 定义/数据/下线提交时，按**新图**把受影响的 active 派生指标加入 dirty；
  下线的派生指标结果被删除、移出 dirty。
* `Recompute()` 对 dirty 集合做增量重算，成功后写入一条 `results` WAL 检查点并清空
  对应 dirty 标记；无 dirty 时为空操作。
* 定义/数据提交与重算由同一把提交锁串行化，且发布前会校验快照未被更新，
  否则放弃纯计算结果并重试——重算期间到达的变更不丢失、不产生陈旧结果。

## 5. 恢复语义

* 仅含 `register / retire / base_update` 的前缀：重放后执行一次全量重算，
  dirty 集合保留为“最后一次检查点之后发生变更的下游指标”。
* 存在 `results` 检查点：以最后一条检查点的结果与 dirty 集合为准；
  检查点之后的定义/数据变更继续累积 dirty。
* 未完成的重算没有 WAL 记录，恢复后不存在“重复应用”或“漏掉已提交变更”的可能。
